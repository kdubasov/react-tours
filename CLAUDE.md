## Архитектура

Это **react-custom-tours** — публикуемая в npm React-библиотека пошаговых подсказок
(«туров»): к блокам страницы по `id` привязываются подсказки, пользователь идёт по
шагам. Пакетный менеджер — pnpm, сборка — Vite (library mode), peer-зависимость
React 19.

### Слои (Feature Sliced Design)

Исходники библиотеки — в `lib/`:

- `lib/app/` — композиционный корень: `context/` (React-контекст тура + провайдер),
  `main.ts` (публичная точка входа, реэкспортит `TipsProvider` и `useTips`).
- `lib/features/` — функциональные блоки: `tips-active-layout/` (оверлей активного тура),
  `tooltip/` (карточка подсказки), `tips-layout/` (монтирование оверлея).
- `lib/shared/` — переиспользуемое без знания о домене: `hooks/`, `types/`, `ui/`, `utils/`.

`src/` — это **демо-приложение** для разработки и e2e, оно НЕ входит в публикуемый пакет.

**Правило слойности:** зависимости идут вниз — `app → features → shared`. Прикладные
shared-хуки (эффекты, побочки) НЕ читают контекст тура напрямую — параметризуй их
колбэками/пропсами (`useEscapeListener(isListen, onEscape)`, `usePropsColors(ref,
customColors, theme)`). Единственное санкционированное исключение — сам аксессор контекста
`useTips` (`useContext(TipsContext)`): он живёт в `shared/hooks` и реэкспортится как часть
публичного API; фичи читают состояние тура только через него.

### Path alias

`@/*` → `./lib/*` (в `tsconfig.json` и `vite.config.ts`). В демо `src/` тоже доступен `@`.

### Публичный API

Внешним кодом импортируются ТОЛЬКО `TipsProvider` и `useTips` (через `dist/app/main`).
Их имена и сигнатуры — публичный контракт, не ломай их без мажорной версии. Внутренние
типы/компоненты можно свободно переименовывать.

## Состояние

Один источник истины — React-контекст `TipsContext` (`lib/app/context/tips.tsx`).
Конфиг тура описывается одним типом `TipsConfig` (`lib/shared/types`), который
переиспользуют и пропсы провайдера, и значение контекста — не дублируй поля по типам.
Список шагов с DOM-узлами (`data`) собирается в провайдере на показе тура; компоненты
читают его из контекста через `useTips`, а не пересобирают.

## Позиционирование

**Подсветка** (`.block`) по умолчанию позиционируется **нативно** через CSS Anchor
Positioning (`anchor-name`/`position-anchor`/`anchor()`/`anchor-size()`), без JS-трекинга
координат. Браузер сам держит её на цели при скролле (в т.ч. вложенных контейнеров) и
ресайзе. Активному узлу `anchor-name` выставляется из JS в `useLayoutEffect` (до отрисовки);
из JS приходит только `--rct-highlight-padding` и `border-radius`.

**JS-фолбэк для движков без `anchor()`** (iOS Safari < 18.2, Firefox < 132): поддержку
детектим один раз (`hasNativeAnchor` в `shared/utils/anchor.ts`). Если её нет — `anchor-name`
на узел НЕ ставим (бесполезен), а `.block` кладём инлайновыми `top/left/width/height` из
`activeItemRect` (`anchorFallbackStyle`), перебивая невалидный CSS `anchor()`. Это НЕ откат к
JS-трекингу как основному пути — на современных движках работает чистый нативный anchor;
фолбэк — деградация, чтобы тур работал везде. Отдельного scroll/resize-листенера фолбэк не
заводит: он переиспользует тот же `activeItemRect`, что уже трекается для тултипа.

**Тултип НЕ использует `anchor()`** — он обычный `position: absolute` внутри `.block`.

> ⚠️ Кроссбраузерный урок: `anchor()` на **интерактивном** элементе ломает хит-тест его
> дочерних кнопок на WebKit/Safari (кнопки становятся некликабельны), причём `position-area`
> и `position-try` тоже. Поэтому тултип позиционируется относительно `.block` обычным CSS,
> а сторона считается в JS:
>
> - `data-v` (CSS: `top`/`bottom`/`overlap`) — выбирается по реальному свободному месту
>   (под → над → поверх для блоков во весь экран). Высоту тултип знает из своего `ref`.
> - горизонталь — инлайновый `left` с клэмпом в `[8, vw-8-width]`, чтобы не вылезал на
>   узких экранах. `itemRect` обновляется на scroll(capture)+resize; `state` меняется только
>   при изменении геометрии — лишних ре-рендеров нет, а `.block` тянет тултип за собой.

- Нативный путь требует Baseline-2026 (Chrome/Edge 125+, Firefox 132+, Safari 18.2+); ниже
  включается JS-фолбэк (см. выше). Не превращай фолбэк в основной путь и не тащи назад
  постоянный JS-трекинг координат на поддерживающих движках — там только нативный `anchor()`.
- e2e **нативного** пути должны `test.skip`, если `CSS.supports('top: anchor(top)')` ложно.
  Тест **фолбэка** (`verify-anchor.spec.ts`) эмулирует отсутствие anchor (stub `CSS.supports`
  + `anchor-name: none`) и гоняется на всех движках. Позиционные тесты — минимум chromium И webkit.

## Соглашения об именовании

- Типы и интерфейсы — PascalCase **без префиксов** (`TipDataItem`, `TipsConfig`).
  Предпочитай `type` алиасу `interface`.
- Локальные пропсы компонента — тип `Props` в самом файле.
- Папки — kebab-case (`tips-active-layout`, `mock-data`).
- Файлы хуков/утилит — camelCase, совпадающий с экспортом (`useEscapeListener.ts`).
- CSS-переменные библиотеки — с префиксом `--rct-` (`--rct-primary`, `--rct-bg-primary`),
  чтобы не конфликтовать со стилями хост-приложения.

## Комментарии

**Вся проза комментариев — по-русски** (inline, JSDoc, обоснования). Идентификаторы,
строки и имена директив — на английском. Комментируй «почему», а не «что»: неочевидные
трюки (например, почему `top: anchor(top)`, а не `top: 10px`), а не пересказ кода.

## Структура модуля: `types/` и `constants/`

- Типы сущности/фичи живут в `types/index.ts`; константы/моки/данные — в `constants/index.ts`.
  Не смешивай типы и runtime-значения в одном файле; плоские `types.ts`/`constants.ts`
  в корне папки не заводи.
- **Никаких магических чисел/строк в логике.** Брейкпоинты, таймауты, пороги, имена якорей
  → именованные константы (`ANCHOR_NAME` в `tips-active-layout` — пример). Повторяющийся
  литерал → одна константа.

## Компоненты и хуки

- **≤120 строк на компонент или хук.** Перерастает — дроби: подкомпоненты в `components/`,
  логику — в узкие хуки.
- **Один компонент/хук = одна ответственность.** Не сваливай несвязанные state/эффекты.
- **Сложную логику выноси в хуки** (эффекты, подписки, деривацию), а не инлайнь в JSX.
- **Без преждевременной мемоизации.** `useMemo`/`useCallback` — только при причине (вход в
  deps эффекта, дорогой расчёт, стабилизация колбэка для мемо-ребёнка).
- **Хук, возвращающий/принимающий колбэк для deps, стабилизирует его сам** (ref или
  `useCallback`), а не прячет через `eslint-disable` (см. ref в `useEscapeListener`).
- **`lib/shared/ui` — презентационный.** Никакого доступа к контексту тура внутри;
  данные и колбэки приходят через пропсы.
- **Переиспользуй перед добавлением.** Сначала смотри `lib/shared`. Повторяется паттерн
  ≥2 раз — выноси общий хук/компонент/утилиту.
- **`ref.current` не кладётся в массив зависимостей** — рефы не триггерят ре-рендер. Эффект
  «навесить слушатель на смонтированный узел» — это `[]`, а не `[ref.current]`.

## Простота важнее абстракций (YAGNI)

Пиши минимальный код под реальный сценарий, а не под «вдруг пригодится». Хелперы/обёртки/
опции заводи при настоящей трансформации или ≥2 реальных потребителях. Сомневаешься —
выбирай меньше кода. Дедуп реального дубля — хорошо; абстракция под единственный случай —
долг.

## Костыли и мёртвый код

- Временное/костыльное решение помечай `TODO` с обоснованием «почему» (не «нестабильная
  ссылка»). Молчаливых костылей не оставляй.
- Удаляй мёртвый код, а не таскай его: неиспользуемые утилиты, моки, опциональные поля
  типов без читателя. Поле/функция без потребителя — мёртвый контракт.

## CSS-конвенции

- **`box-sizing: border-box`** на коробочных элементах, иначе `max-width`/`min-width` не
  учитывают паддинг и элемент вылезает за вьюпорт.
- **Раскладку задавай через `grid`** (`grid-template`, `gap`) на контейнере, а не через
  `flex-grow`/`flex-shrink`/`flex-basis` на детях.
- **Только чётные `font-size`** (12, 14, 16, 18, 20…).
- **Размер иконок — через `font-size`/`scale`**, не дублируй фиксированными `width`/`height`,
  где можно масштабировать.
- **Без `!important`.** Конфликт решай специфичностью селектора с комментарием.
- **Никакого статического хардкода в inline `style`.** В CSS-модуль. Inline `style`
  допустим только для по-настоящему динамических значений из пропсов/состояния
  (например `--rct-highlight-padding`, `border-radius` узла).
- **Не задевай глобально хост-приложение.** Селекторы `*`/тег-селекторы в CSS-модулях
  НЕ скоупятся и протекают на страницу пользователя — избегай их (используй классы).

## Брейкпоинты

Мобильные медиа — `@media (max-width: <bp>px)`. Используй существующие брейкпоинты
(`1024`, `560`, `375`), не выдумывай разовые. Тултип ниже `560px` переключается на
полноширинный режим — учитывай это при правках стилей подсказки.

## Тесты

- Тест-раннер — только Playwright e2e (`e2e-tests/`). `tests.spec.ts` — базовый флоу;
  `verify-anchor.spec.ts` — регресс позиционирования (видимость, совпадение подсветки,
  скролл вложенного контейнера, узкий экран).
- Регресс на сложную визуальную логику добавляй в `verify-anchor.spec.ts`. Разовые
  диагностические спеки удаляй до коммита.
- Меняешь позиционирование/адаптив — прогоняй `verify-anchor` на chromium и проверяй,
  что тултип в пределах вьюпорта и не перекрывает блок без необходимости.
